# 云枢智慧城市数据平台未完成功能补全 PRD

## 1. 背景

当前云枢智慧城市数据平台已具备登录注册、首页仪表盘、仪表盘/图表只读列表与详情、AI 助手和个人中心，但构建仍被既有 TypeScript 错误阻断，且图表编辑器、仪表盘写操作、用户管理、角色权限管理尚未完成。

本期在现有 React 19、Ant Design 6、Redux Toolkit、ECharts 和 Axios 技术栈上补齐明确需求，不重写项目，不实现尚未总结需求的地图与 3D 场景。

## 2. 本期目标

1. 修复现有构建基线与关键鉴权缺陷，使 `npm run build` 成功。
2. 完成图表新建、编辑、预览、保存和删除。
3. 完成仪表盘新建、编辑、克隆、级联删除、添加图表和实时详情。
4. 完成用户列表、筛选、新增、编辑、头像上传、状态切换、密码重置和删除。
5. 完成角色列表、新增、编辑、权限配置、用户数统计和删除。
6. 页面样式与 `/Users/aaron/react项目需求` 中的示例图保持统一。

## 3. 非目标

- 不实现地图可视化和 3D 场景；等待后续需求总结。
- 不新增 Swagger 支持但需求截图未要求的 `table` 图表类型。
- 不把所有代码强制改成 TypeScript；仅在现有 TS 主链和必要边界补充类型。
- 不实现依赖后端新增契约的“动态前端权限驱动菜单”。
- 不移除用户头像，仅支持上传和替换。
- 不修改 `root` 或其他非授权测试账号的数据和仪表盘。

## 4. 用户与权限

- `super_admin`：拥有全部管理能力，但内置超级管理员账号受到前端保护。
- `admin`：可以管理用户、角色、图表和仪表盘。
- `analyst`：可以新建、编辑、克隆仪表盘和管理图表，但不能删除仪表盘。
- `user`：以只读查看能力为主。

前端权限只用于界面和路由体验，后端 RBAC 仍是最终安全边界。

## 5. 功能需求

### 5.1 构建与鉴权基线

- 为 Redux 登录状态、选择器、ECharts 公共组件和接口数据补充正确类型。
- 清理或修正阻断构建的旧引用、隐式 `any` 和未使用变量。
- 无法解析的 token 必须按无效 token 处理。
- HTTP/业务 401 时清理本地登录状态并跳转登录页。
- 用户资料为空时布局不得崩溃。
- 首页首次加载、自动刷新和 AI 流式请求失败时必须正确收尾。

### 5.2 图表管理与四步编辑器

#### 列表

- 支持仪表盘筛选、重置、刷新、新建、预览、编辑和删除。
- 删除前弹出确认框，成功后刷新当前页。

#### 四步编辑器

1. 选择目标仪表盘：支持从仪表盘卡片进入时自动预选。
2. 配置数据：使用云枢智慧城市数据平台内置数据源，通过接口动态获取表和字段；选表前不显示字段选择。
3. 选择类型：填写标题并选择柱状图、折线图、饼图或散点图。
4. 预览保存：查询数据源并在前端构建 ECharts 配置；支持重新生成预览、保存到仪表盘或保存修改。

#### 数据规则

- X 轴为分类/维度字段，Y 轴为数值字段。
- 内置五张表显示中文名称和辅助说明，但真实表/字段来自接口。
- 保存 `queryConfig` 作为动态查询依据，同时保存 `chartConfig` 作为样式/回退配置。
- 新建使用 `POST /charts`，编辑使用 `PUT /charts/{id}`。
- `/chart/add` 和 `/chart/new` 均进入同一新建流程。

### 5.3 仪表盘管理

- 列表展示标题、描述、图表数量和主题。
- 新建/编辑字段：标题必填、描述可选、浅色/深色主题。
- “添加图表”直接进入图表编辑器并预选当前仪表盘。
- 克隆成功后停留在列表并提示。
- 删除确认必须说明会级联删除关联图表和地图图层。
- 分析师不展示仪表盘删除入口。
- 详情页对每个图表查询最新数据；单图失败不影响其他图表展示。

### 5.4 用户管理

- 支持用户名、状态和角色筛选，支持查询、重置和每页 10 条分页。
- 列表字段：序号、ID、头像、用户名、邮箱、角色、状态、最后登录、创建时间、操作。
- 新增字段：用户名、密码、邮箱、头像、角色；用户名失焦检查重复。
- 编辑时用户名只读，可修改邮箱、头像、角色和状态。
- 状态切换前确认，请求失败时保持原状态。
- 密码重置前确认；成功后只显示一次 8 位新密码并提供复制按钮。
- 删除前提示不可恢复；有关联数据时展示后端拒绝原因。
- 当前登录账号、用户名 `root`、角色编码 `super_admin` 的账号禁止禁用、重置密码和删除。

### 5.5 角色权限管理

- 列表字段：序号、角色名称、编码、描述、用户数、状态、操作。
- 每个角色通过用户分页接口查询 `total` 作为用户数。
- 新增角色：名称、唯一编码必填，描述可选。
- 编辑角色：编码只读，名称和描述可修改。
- 权限项来自 `GET /permissions`，使用 Ant Design Tree 父子级联勾选。
- 权限保存为全量覆盖；未能可靠获取已有权限 ID 时禁止保存，避免清空权限。
- 兼容角色详情中常见的 `permissionIds`、`permissions` 等返回形态。
- `super_admin` 禁止删除，也禁止保存空权限。
- 其他角色删除前确认；有关联用户时允许后端返回具体拒绝原因。

## 6. 接口范围

- 仪表盘：`GET/POST /dashboards`、`GET/PUT/DELETE /dashboards/{id}`、`POST /dashboards/{id}/clone`。
- 图表：`GET/POST /charts`、`GET/PUT/DELETE /charts/{id}`、`POST /charts/{id}/query|preview`。
- 数据源：`GET /datasources`、`GET /datasources/{id}/tables`、`GET /datasources/{id}/tables/{table}/fields`、`POST /datasources/{id}/query`。
- 用户：`GET/POST /users`、`GET/PUT/DELETE /users/{id}`、用户名检查、状态切换、密码重置。
- 角色：`GET/POST /roles`、`GET/PUT/DELETE /roles/{id}`、权限树和角色权限全量保存。
- 文件：`POST /upload/avatar`。

所有受保护请求必须携带 Bearer token；业务响应统一按 `{ code, message, data }` 处理。

## 7. 测试数据安全红线

- 真实头像上传、状态修改、密码重置测试仅允许作用于用户名 `NormalAdmin`。
- `NormalAdmin` 的已知测试密码为 `admin123`，不得写入源码、文档、日志或提交记录。
- 禁止修改、禁用、重置或删除 `root`。
- 禁止新增、编辑、克隆或删除 `root` 名下的任何仪表盘。
- 禁止修改其他用户账号。
- 优先使用构建、静态检查、只读接口和前端交互验证；非必要不执行真实写操作。
