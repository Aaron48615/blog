## RBAC：按角色决定要展示的菜单
RBAC 按角色决定展示菜单主要分为四步。首先，我在菜单配置中为每个菜单设置允许访问的角色，例如给系统管理菜单配置 super_admin 和 admin。用户登录成功后，后端会返回用户信息和角色编码，前端从 Redux 中获取当前用户的 roleCode。
然后遍历所有菜单配置，判断当前角色是否存在于菜单的 roles 数组中，只保留符合条件的菜单，并将过滤后的结果保存为 menuItems。如果是带有子菜单的一级菜单，则由一级菜单的角色权限控制整个菜单及其子菜单的展示。
最后，将过滤后的 menuItems 传给 Ant Design 的 Menu 组件，这样不同角色登录后看到的左侧菜单就会不同。这个功能主要负责控制菜单的显示，用户直接输入地址访问页面时，还需要配合页面路由守卫再次校验权限。

## 面包屑：显示面包屑路径名
给按角色过滤的菜单循环，只有一级菜单的只需要把key值和location.pathname匹配，有二级菜单的就找key值和location.pathname相同的，，然后返出符合条件的对象currentMenu。因为currentMenu是随着location.pathname变化的，所以使用useMemo做缓存。页面中展示使用currentMenu.label

## 切换主题
我把主题状态放到了 Redux 的 themeSlice 中，通过 mode 保存当前是明亮还是暗色主题。入口文件中使用 ConfigProvider，根据 mode 切换 antd 的 defaultAlgorithm 和 darkAlgorithm。布局组件里的 Switch 负责修改主题的 action，Sider、Menu 和页面中的 antd 组件会根据主题自动更新。因为使用了 redux-persist，刷新页面后主题选择也会保留。

## 控制刷新页面后自动展开二级菜单
我用组件库的 `openKeys` 和 `selectedKeys` 控制菜单。
首先根据当前路由设置 `selectedKeys`，让刷新后当前二级菜单保持选中；然后在页面首次加载时，根据当前路由找到对应的一级菜单，把它的 `key` 设置到 `openKeys` 中，让一级菜单自动展开。用户手动展开或收起菜单时，通过 `onOpenChange` 更新 `openKeys`。这里不能监听 `location.pathname`，否则每次切换二级菜单都会重新设置 `openKeys`，导致其他菜单自动合上。

## RBAC: 页面路由守卫控制角色能访问哪些页面
RBAC 页面路由守卫主要分为四步。首先我在路由守卫中维护一个路由权限映射表，把每个页面路径和对应的访问权限关联起来，例如 /users 对应 users:view。然后拿用户要访问的路径在权限映射表中做匹配，把允许访问的权限标识字段存在permission里，然后用封装好的方法判断这个权限标识在不在用户角色的权限列表内，如果在就返回true，不在返回false。最后如果permission存在且方法返回的为false，就直接跳转到403页面。
这样可以防止用户仅通过手动修改地址栏，就访问自己没有权限的页面。










## 项目重要的点
登录鉴权、RBAC权限模型
*怎么鉴权*：首先用户前端去输入用户名和密码，然后点击登录时要获取登录名和密码（vue3项目对密码做了AES加密，注意要说明），将用户名和密码传给后端，后端根据用户名和密码进行匹配，如果是用户的话，就返回一个令牌token，前端接收回显的数据中如果包含这个token，就说明用户存在，我把这个token存到状态库中（或者本地存储中），接着进入登录页面。因为有些数据是需要去校验你是否是系统用户登录，所以我在封装请求拦截器时携带token，在请求头里携带，通过请求头中的Authorization字段，一般是Bearer单词拼上token（即Authorization: Bearer <token>）一起返给后台，后台通过返的东西去校验接口，请求的时候是否是我的用户
*无感刷新*：我封装了一个校验token是否过期的方法，我会在过期的前20秒让他重新发起token的请求（还有很多方式，比如用户正在浏览的话，就发起登录请求重新登录，或者给用户提示等等）
*RBAC权限校验怎么做的*：1. 做权限表的设计，什么角色对应什么页面和页面功能，比如super_admin就对应*通配符，代表所有功能都能用，不同的权限对应不同的表。2. 封装了一个hook方法hasAuthority，查看你传入的表是否在我的权限表中存在，不存在就不允许访问
