### 8.2 技术方案

1. **依赖与加载边界**
   - 安装 `three`、`@react-three/fiber`、`@react-three/drei` 和 `@types/three`。
   - 保留路由的懒加载，确保 Three.js 只进入 `/scene` 的异步代码块，不增加登录页和仪表盘首屏负担。
   - 使用 React Three Fiber 的 `Canvas` 管理 WebGL 渲染器，用 Drei 的 `OrbitControls`、`RoundedBox` 和 `Html` 实现交互、圆角柱体与标签。

2. **城市接口与数据模型**
   - 以项目根目录的 `字段.md` 作为字段语义依据：城市数据来自 `cities`（城市基础信息）表。
   - 在 `src/api/cities.ts` 增加共享 `CityRecord` 类型和 `GET /cities` 方法，字段与 `字段.md` 对齐：`id`、`name`、`province`、`population`、`area`、`gdp`、`lng`、`lat`。
   - 本期 3D 页只消费 `id`、`name` 和 `population`；`area`、`gdp`、`lng`、`lat` 保留在共享类型中供未来地图页使用，不据此扩大简版 3D 的功能范围。
   - `字段.md` 已明确 `population` 的单位是“万”，因此接口原始值只做 `Number(...)` 转换和千分位格式化，禁止再次除以 `10,000`；界面单位统一写成“万人”。
   - 对人口执行有限数校验，过滤 `null`、空字符串、`NaN`、无穷值和负数，再按人口降序排列并限制合理的展示数量。
   - 接口失败显示 `Alert + 重试`，空数组显示 `Empty`，加载过程显示 `Spin`；不使用假数据掩盖接口问题。

3. **场景数据映射**
   - 计算最大人口 `maxPopulation`，每根柱高按 `population / maxPopulation` 归一化，并设置最小高度，避免小城市完全不可见。
   - 城市按索引等角度排列到固定半径圆环：`angle = index / count * 2π - π/2`，坐标为 `x = cos(angle) * radius`、`z = sin(angle) * radius`。
   - 颜色从受控色板按索引取模，避免城市数量超过色板长度后出现无效材质。
   - 城市标签读取 `name`（名称），数值读取 `population`（人口〔万〕）；界面显示单位为“万人”，数值使用本地化千分位格式。

4. **Three.js 组件职责**
   - `ScenePage`：请求数据、管理加载/错误/空态、读取 AntD 主题并承载 Canvas。
   - `SceneSetup`：配置背景、雾效、环境光、方向光、半球光、地板、环形底座、网格和相机控制。
   - `CityBar`：绘制底部光环、圆角柱体、顶部光环、Hover 光柱、城市名称与人口标签。
   - `Ring`：封装重复使用的环形几何体与透明材质。
   - 简版优先在 `src/pages/Scene.tsx` 内保持局部组件，不为少量逻辑提前拆出过多文件；样式集中到 `src/css/Scene.css`。

5. **动画与交互**
   - 使用 `useFrame` 让柱体按城市顺序延迟从 Y 轴生长，动画完成后停止继续计算缩放值。
   - Hover 时提升材质发光强度、显示透明光柱，并在场景左上角显示城市和人口；移出时恢复。
   - `OrbitControls` 开启阻尼，限制俯仰角和远近距离，防止相机钻入地面或把场景缩放到不可操作。

6. **主题、尺寸与降级**
   - 页面层读取 `theme.useToken()` 和全局主题，将背景、网格、文字、雾效和浮层颜色作为明确参数传入场景组件。
   - Canvas 容器设置稳定高度、圆角和 `overflow: hidden`；移动端降低高度和标签字号。
   - 使用 `ResizeObserver` 或 Canvas 自带尺寸同步适配 Layout 的内部滚动容器，不能只依赖 `window.resize`。
   - WebGL 不可用或 Canvas 初始化失败时显示可理解的降级提示，不让整条路由白屏。

7. **资源与性能约束**
   - 自建 `CanvasTexture` 在 effect cleanup 中执行 `dispose()`，同时恢复场景背景和雾效，兼容 React StrictMode 的重复挂载检查。
   - 限制 `dpr` 上限，避免高分屏无意义地放大 GPU 消耗；城市数量按接口数据规模设置上限。
   - 不保留调试日志；所有列表元素使用稳定的城市 ID 作为 key。

### 8.4 字段使用清单

| 字段 | `字段.md` 定义 | 3D 本期用途 | 地图未来用途 |
| --- | --- | --- | --- |
| `id` | 城市唯一标识（接口基础字段） | React key、稳定识别城市 | 关联环境接口 `/cities/:id/environment` |

| `gdp` | GDP（亿元） | 不使用 | 总 GDP 统计、城市信息窗 |
| `lng` | 经度 | 不使用 | Marker/Circle 横向坐标 |
| `lat` | 纬度 | 不使用 | Marker/Circle 纵向坐标 |

> `字段.md` 是字段名称和单位的设计依据，但它不是运行时代码模块。实现时通过 `src/api/cities.ts` 的类型固化契约，不从 Markdown 动态读取字段。

### 9.3 数据与接口计划

- 复用 `src/api/cities.ts` 已有的 `CityRecord` 和 `GET /cities`，兼容数组与分页两种响应并统一解包。
- 城市字段按 `字段.md` 使用 `id`、`name`、`province`、`population`、`area`、`gdp`、`lng` 和 `lat`；无效经纬度不得创建覆盖物。
- `population` 原始单位已经是“万”，统计总人口时直接求和并显示“万人”，不得再次除以 `10000`；GDP 直接求和并显示“亿元”。
- 在 `src/api/cities.ts` 增加环境记录类型和 `GET /cities/:id/environment` 方法。
- 环境模式严格按 `/cities` 接口返回顺序取前 `10` 个城市并发请求环境数据，不按人口重新排序。
- 环境响应兼容数组与分页结构；存在多条记录时优先按记录时间选择最新一条，缺少可靠时间字段时才使用接口返回的第一条。
- 环境信息窗本期展示 `aqi`、`pm25` 和 `weather`；`pm10`、`temperature`、`humidity`、`noise` 等返回字段可保留在类型中，但不强制展示。
- 使用 `Promise.allSettled` 处理环境请求：部分失败时继续展示成功城市并给出“部分城市数据获取失败”提示；全部失败或完全无数据时显示明确错误或空态。
- 环境统计只基于成功取得有效环境记录的城市；无有效数据时平均 AQI 显示 `--`，不得产生 `NaN`。

### 9.4 地图生命周期计划

1. 页面挂载后并行加载城市数据和高德 JS API 2.0；地图容器始终挂载，加载和错误状态使用容器内遮罩，不能因状态切换移除容器。
2. SDK Promise 和地图初始化保持幂等，兼容 React StrictMode 的开发态重复 Effect；异步任务使用失效标记，防止卸载后更新状态。
3. SDK 加载成功后只创建一次 `AMap.Map`，实例保存到引用中；数据到达和模式切换只能更新覆盖物，不能重建地图。
4. 全页复用一个 InfoWindow，点击不同覆盖物时只更新内容和位置。
5. Marker、Circle 及其事件分别保存；切换模式时关闭 InfoWindow、解绑旧事件并清除旧覆盖物，防止叠加。
6. 页面卸载时移除覆盖物、关闭信息窗、注销事件、解除 `ResizeObserver` 并调用 `map.destroy()`。
7. 使用 `ResizeObserver` 处理侧边栏展开、收起和内容区尺寸变化，必要时调用地图尺寸刷新能力。

### 9.5 覆盖物与交互计划

- **城市标记模式**：为每个有效城市创建 Marker 和常驻城市名称；点击后安全展示省份、人口、面积和 GDP，并将地图平滑居中、放大到该城市。
- **环境监测模式**：为成功取得环境记录且坐标有效的城市创建 AQI Circle；点击后展示城市、AQI、PM2.5 和天气，并将地图平滑居中、放大。
- 初次进入和切换模式时均保持用户确认的北京中心、缩放级别 `11`，不调用全国覆盖物自动视野适配。
- AQI 颜色、半径和统计分类共用一套纯函数：`<= 50`、`<= 100`、`<= 150`、`> 150`；污染城市统一按 `> 150` 统计。
- Circle 半径设置最小值和最大值，防止异常 AQI 使圆形不可见或覆盖范围过大。
- InfoWindow 使用 DOM 节点和 `textContent` 构造内容，不直接拼接服务端 HTML，规避 HTML 注入。
- Key 缺失、SDK 加载失败、城市接口失败、环境接口失败、空数据和坐标无效均提供可理解的反馈。

### 9.6 统计与视觉计划

- 环境模式展示“监测城市、平均 AQI、空气优良、污染城市”四项统计；部分失败时统计不得把失败城市计入监测总数。

### 10.2 当前问题与修复目标

1. 当前编辑器直接展示单表原始字段，`city_id` 会成为坐标轴实际值，用户看到的是数字而不是城市名称。
2. 当前 Y 轴主要依赖数据库字段类型判断，虽然能阻止部分文本字段，但无法表达“设施数量”“事件数量”等不存在于表中的统计指标。
3. 当前预览按原始记录绘制；当 X 轴存在重复城市、类型或日期时，图表缺少计数、求和、平均值等聚合语义。
4. 时间字段按完整时间戳展示会产生大量几乎不重复的 X 值，需要固定按天归组。
5. 预览阶段的前端转换如果没有随图表配置持久化，保存后仪表盘重新查询会和创建时预览不一致。
6. 修复目标是在不修改后端业务数据和数据库结构的前提下，让字段显示、预览、保存后实时展示保持同一套前端转换规则。

### 10.3 前端字段模型

- 在前端为字段补充展示元数据，但不改变接口返回的原始字段：
  - `sourceField`：真实字段名，例如 `city_id`、`lng`、`recorded_at`。
  - `label`：业务名称，例如“城市名称”“经度”“记录时间”。
  - `dataType`：兼容接口的 `dataType` / `type`。
  - `relation`：已知关联信息；本期仅实现 `city_id -> cities.id -> cities.name`。
  - `isTime`：是否需要按天格式化和分组。
  - `isNumeric`：是否可作为普通数值 Y 轴。
- X 轴保留所有具备有效字段名的原始字段，包括 `id`、`city_id`、经纬度、文本和时间字段。
- Y 轴保留所有数值字段，包括 `id`、`city_id` 和经纬度；同时增加前端虚拟选项“记录数量”。文本字段不能作为普通数值 Y 轴，避免再次生成空白图。
- 虚拟“记录数量”只存在于前端 UI 和转换元数据中，不在业务表中创建字段，也不向业务表写入结果。
- 选择 `city_id` 作为 X 轴时，查询仍使用物理字段 `city_id`；前端额外只读加载城市列表并建立 `Map<number, string>`，将 X 值映射成城市名称。
- 城市映射缺失时显示可理解的降级值，例如“未知城市（ID: 123）”，不能静默丢弃整条记录。

### 10.4 X/Y 轴与统计方式交互

1. **配置顺序**
   - 用户先选择数据表，再手动选择 X 轴、Y 轴和统计方式。
   - 切换数据表时清空 X/Y/统计方式和旧预览，防止不同表字段串用。
   - 不自动填入任何默认组合；“下一步”和“生成预览”必须等待必要配置完整。

2. **统计方式**
   - 普通数值 Y 轴提供“不聚合、求和、平均值、最大值、最小值”。
   - Y 轴选择“记录数量”时，统计方式固定为“计数”，不再要求用户选择真实数值字段。
   - 计数以通过有效性检查后的记录条数为准；求和、平均、最大、最小只处理可转为有限数字的 Y 值。
   - 若全部 Y 值无效或查询结果为空，停留在配置步骤并显示明确错误，不进入只有坐标轴的空白预览。

3. **分组规则**
   - 有统计方式时，按转换后的 X 轴展示值分组；相同城市名称、类型或日期合并为一个数据点。
   - 时间字段统一按本地日期格式 `YYYY-MM-DD` 分组，本期不增加小时/月粒度选项。
   - “不聚合”保持原始行顺序；对于重复 X 值仍逐条绘制，作为用户明确选择的结果。
   - 聚合完成后再执行图表展示数量限制，不能先截取前 50 条原始记录再聚合，以免统计结果失真。

4. **字段显示**
   - 字段选择器显示“业务名称（原字段名）”，例如“城市名称（city_id）”“经度（lng）”“记录 ID（id）”。
   - 图表坐标轴名称使用业务名称；Tooltip 可补充原字段名，但不得用原字段名替代主要业务名称。

## 阶段 11：Token 无感刷新与登录过期兜底（已实施）

### 11.1 后端约束与刷新策略

- 后端提供 `POST /api/auth/refresh`，请求不需要 Body，但必须通过 `Authorization: Bearer <旧 Token>` 携带仍有效的旧 Token；返回数据沿用登录接口的 `{ token, user }`。
- 刷新接口要求认证，因此前端固定在 JWT 实际到期前 `30` 秒主动刷新；真正过期后不再伪造或直接重新请求 Token，而是提示用户重新登录。
- 主动刷新遇到网络错误或服务端 5xx 时，每隔 `5` 秒重试，并且只在旧 Token 真正过期后触发登录过期提示。
- 本阶段沿用后端的单 Access Token 方案，不额外假设存在 Refresh Token，也不修改后端接口、数据库或业务数据。

### 11.2 前端实现

- 新增 `src/utils/authToken.ts`，统一完成 Base64URL JWT 解析、真实过期判断、提前刷新时间计算、请求重试判定和 single-flight 并发锁。
- 新增 `src/services/authSession.ts`，通过不注册普通拦截器的独立 Axios 实例调用刷新接口；并发刷新请求共享同一个 Promise，成功后统一更新 Redux 中的 `token` 和 `user`。
- 刷新响应写入 Redux 前会校验当前 Token 是否仍是发起刷新时的 Token；用户在请求期间主动退出或切换账号时，迟到响应不会重新写回登录状态。
- 新增全局 `SessionManager`，只在 `ConfigProvider` 内挂载一次；Token 更新、退出登录和组件卸载时都会清理旧定时器，兼容 React StrictMode 的重复副作用检查。
- Axios 请求拦截器始终使用 Redux 中的最新 Token；HTTP 401 和业务状态码 401 会刷新并重放原请求一次，再次失败后停止重试。
- 登录、注册和验证码请求增加 `skipAuth` / `skipAuthRefresh` 标记，避免公开认证接口的失败响应错误触发刷新和过期弹窗。
- `UseAuth` 不再把“距离过期 20 秒”直接视为过期；实际过期时先阻止受保护页面渲染，由全局 Ant Design Modal 提示重新登录。
- 登录过期弹窗不可关闭、不可点击遮罩取消且全局只显示一个；确认后清空登录状态并使用 `replace` 跳转 `/login`。
- AI 流式请求在每次发送时读取最新 Token；开始读取 SSE 数据前遇到 401 时刷新并重试一次，已经开始返回的数据流不会重复提交。
